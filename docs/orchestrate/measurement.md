# 工場の計測の決まり（窓口）

窓口が工場（`packages/factory`）の変更前後を測るときの決まりと罠である。読み方と直し方の正本は
[`workspace/mvp/m1/agent/methodology/`](../../workspace/mvp/m1/agent/methodology/README.md)、
計測の段取り（U0〜U3）は設計書 08。2026-11-18 に、窓口の Claude Code の auto memory から移した（#968）。

## 1. 費用

- **OpenAI での計測は 1 日 4 USD まで**（所有者 2026-11-09）。超えそうなら走らせる前に所有者に聞く
- 一気通貫（U0）は節目だけ。wave ごとは工程の評価（U1〜U3）にする
- LLM への要求が比較元とバイト列で同じ変更（記録・診断の追加など）は実計測しない（偽物の LLM の試験と独立レビューで足りる）
- まず 10 題材 × 1 本でふるい、差がはっきりしないときだけ × 3 にする。比較元は手元の記録を流用し、毎回測り直さない
- v1.1α を毎回の前後比較に含めない（所有者 2026-10-19）
- 費用の考え方は CLAUDE.md の「先に安い手を試す」に従う。新しい道具を作る前に既存の道具（探針の入口 `factory:plan-probe` など）の再利用を先に考える

## 2. 何で測るか

- **標準の組み合わせ**（所有者 2026-11-09）：上流（C1〜C3）luna medium → T2 だけ terra high → B 以降 luna medium。改善の比較の基準はこれにする
  - 工場の口：`--effort medium --stage-effort test-spec=high --stage-model test-spec=gpt-6.1-terra --budget 2`。**予算は 2.00 を明示する**（1.00 では T2 の予約が同時の開始で通らず 1/3 が止まった）
  - 基準線（11-10・2e5d3da・10 題材 × 3）：外 PASS 23/30・壁時計の中央 213 秒
- **UX を体験できる線**（所有者 2026-10-24）：一気通貫の成功 21/30 以上・1 本 300 秒以下。2026-11-16 から、この線は Plan を含む（節目に Plan→Build を 30 本通して位置を出す）
- **Plan の主指標**（所有者 2026-11-16。#951 のコメント）：確定数ではなく「黙った欠落の無い確定」と、条件 × 適用先の保持率（凍結した正解の表）で読む
- **Ollama は 2026-11-23 まで計測しない**（所有者 11-09：月の利用枠が尽き、課金しない方針）。使うときも先に所有者に確かめる。Ollama は定額なので USD の上限は効かず、利用枠・429・同時数を見る。json_schema が応答を縛らないので、形の誤りの数を必ず見る。deepseek は `deepseek-v4.1-flash:1017-cloud` を `--model` で明示する

## 3. 読み方

- **流す前に読み方を書く**（`preregistered.md`）。流した後に線を変えたら、逸れとして追記する
- **揺れの幅**：20 本は同じ工場でも確定 ±2・問いの前の停止 ±3 揺れる（2026-11-14）。害の目安は 30 本で確定 −5・停止 +4 にする
- **直しが働いた件数を必ず数える**。働いていなければ、差は揺れと読む（#942 の教訓）
- 採点は凍結した正解の表で、側（前・後）を伏せて頼む

## 4. 記録の置き場所

- **計測は固定した候補で流す**：管理が作り直しうる統合候補の worktree を直接指さない。別の detached worktree に固定して build してから流す。途中で dist が変わると、条件の指紋（起動時に 1 回だけ取る）と食い違う（2026-10-13）
- **記録は tmp に置かない**：凍結した組・比較元の計測・採点の出力は、作ったらすぐ `workspace/mem/archive/<日付>/` に写す（git の外。.gitignore 済み）。scratchpad は一時の出力だけ（2026-10-20 に古いファイルが消え、比較元を取り直した）
- 記録の費用の欄：#829（段ごとの単価）より前の記録は、terra の分を luna の単価で数えている。実費はトークン数から計算し直す
