## 2. rubric v4 の判定（要件 → 採点）

名前は見ない。役割は構造と選択肢の表示名で見つけ、**見つからなければ不合格**（第 2 段の決定 1・2）。振る舞いは spec-engine の評価器に値を入れて確かめる（時計は 2026-10-08 12:00 JST に固定）。**「見られる」は、表・一覧・ボードの `show`、ダッシュボードの `number`・`bar`・`pie` の `value`、`ranking` の `by` と `show` のどれかに出ていること**（決定②）。

| 題材 | 役割の見つけ方 | 要件ごとの判定 |
|---|---|---|
| A 持ち寄り | メンバー（ref で指され文字列の項目を持つ）を指し、選択肢「料理／飲み物／道具」「まだ／用意できた」の 2 つの enum を持つ entity | 登録したときの状態＝まだ／「用意できた」にする update が「まだ」でだけ許される／状態の列のボード／両方を登録できる／種類と人で絞り込み／数 0 で検査が落ち 1 で通る／人ごとの数（m1 2 件・m2 1 件で 2・1）が見られる |
| B 当番表 | 同上（「ゴミ出し／公園の掃除／夜回り」「予定／済み」） | 登録したときの状態＝予定／「済み」ボタンの条件／状態の列のボード／登録／絞り込み／印が今日だけ真（昨日・明日は偽）／人ごとの回数が見られる／**メンバーの ranking があるなら、回数の少ない人が上に来る**（決定①。負の数で書いたら ui_note に記録） |
| C 会費 | メンバーを指し、「現金／振込／送金アプリ」の enum と数・日付の項目を持つ entity | 登録／金額 0 で落ち 1 で通る／update と delete がある／人ごとの合計（100＋400＝500）が見られる／今月の金額 300・件数 2 がダッシュボードの number に出る（9 月の 400 を含めない）／月ごとの合計（日付で月ごと・`last: 6`・sum）が bar に出る／払い方ごとの集計が pie か bar に出る／人と払い方で絞り込み |
| D 出欠 | メンバーの並び（`list of`）と、数・日付・文字列の項目を持つ entity | 登録／定員 2 に 3 人で落ち 2 人で通る／定員 0・0 人で落ち、定員 1・1 人で通る／参加人数 2 と残り 3（定員 5・2 人）が見られる／人ごとの参加回数が見られる。**「0 人で登録」は書けないので宣言では採点しない**（申告で採点） |
| E 貸し出し | 文字列の項目を持つ 2 つの entity を ref で指し、「貸出中／返却済み」の enum と日付を持つ entity | 登録したときの状態＝貸出中／「返却済み」ボタンの条件／状態の列のボード／3 つとも登録できる／印が昨日の期限で真・今日と明日で偽／備品ごと・人ごとの回数が見られる。返却済みに印が残るのは合格（第 1 段の決定 3） |

**申告の採点**（`score-claims.mjs`）：最後の試行の `unwritable` を、題材ごとの「書けない要件」（B「少ない順」・D「0 人で登録」。A・C・E は無し）と言葉の部分一致で照合し、**正しい申告／挙げ漏れ／誤った申告**を数える。B の「少ない順」を宣言で書けた場合は、申告してもしなくてもよい（決定①）。**誤った申告は人が中身を確かめる**（第 1 段の判定が外れている可能性があるため。§5 の 1）。

## 5. 気づいたこと（流す前に知っておくこと）

1. **P1-r2 の「誤った申告」は、語彙の穴を正しく指していた可能性がある。** 申告の中身は「ボタンの表示名を指定する語彙が無い」で、契約の `updateAction` は `name`・`entity`・`kind`・`set`・`when` しか持たず、**表示名（`label`）が無い**のは事実である。要件の「『用意できた』にするボタン」は、状態を変える動きであって表示名の指定ではないので、採点は「誤った申告」のままにするが、**操作の表示名が書けないことは語彙の穴として記録する**（第 1 段の §6 の表に足す候補）
2. **キャッシュが題材をまたいで効かない。** `run.mjs` は入力を「要件 → 文書」の順に並べているので、共通の前置き（文書）より前に要件が来て、キャッシュは同じパターンの 2 回目以降にしか効かない。**凍結の条件なので第 5 段では変えない**が、プロダクト内の工場では「文書 → 要件」の順にすれば、ほぼ全部の呼び出しでキャッシュが効く（入力の費用が約 1/10）
3. **D の「定員は 1 人以上」の判定には限界がある。** 参加者を 1 人以上の必須にした宣言では「定員 0・0 人」を作れないが、評価器はその組を評価できるので判定は回る。ただし「定員の検査は無いが、参加人数の下限の検査がある」宣言を区別できない
4. **申告の照合は言葉の部分一致である。** 当たらない書き方で正しく申告したものは「挙げ漏れ＋誤った申告」と出る。`summary.md` の申告の列が NG のものは、人が中身を確かめる
