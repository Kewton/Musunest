## 目的

**アプリの宣言（`app.spec.yaml`）を、文書だけを読んで書けるか**を確かめる試行の、**第 0 段（疎通確認）**です。今回は**成績を測りません。** 依頼の受け渡し・出力の取り出し・採点・記録が一通り回るかを確かめます。

## 書いてほしいもの

次の要件のアプリの宣言を 1 つ書き、**`trial/app.spec.yaml`**（この worktree の直下の `trial/` ディレクトリ）に保存してください。

> **読書会の記録アプリ**
> - メンバー（名前）を登録できる
> - 本（書名・著者）を登録できる
> - 読書会（開いた日・取り上げた本・参加したメンバー）を記録できる
> - 本ごとに、取り上げた回数が分かる
> - 今月開いた読書会の回数が、ダッシュボードで分かる
> - メンバー・本・読書会は、それぞれ一覧で見られ、画面から追加できる

## 読んでよいもの（これ以外は読まないでください）

- `packages/appspec-schema/contract/`（宣言の構造の JSON Schema・式の文法・規則の表）
- `packages/appspec-schema/docs/semantics.md`（語彙の意味）
- `packages/appspec-schema/vocabulary.yaml`（語彙の台帳）

**見本・テスト・負例・`git` の履歴は読まないでください。** 書き方の例を見ずに、文書だけで書けるかを確かめる試行です。

## 触ってはいけないもの

- `trial/app.spec.yaml` 以外のファイルを作らない・変えない
- `git` の commit・push・branch の操作をしない
- 静的チェックなどのコマンドを実行しない（採点は窓口が行います）

## 返してほしいこと（返信の本文。30 行以内）

1. 保存したパス
2. **実際に開いたファイルの一覧**（読んでよいもの以外を開いたなら、それも正直に）
3. **文書から読み取れなかったこと・迷ったこと**（どう解釈して書いたか）
4. 要件のうち、**文書を読む限り書けないと判断したもの**があれば、その理由

## 締め方

最後に `DONE:` で始まる 1 行で締めてください（例：`DONE: trial/app.spec.yaml に保存 / 迷った点 3 / 書けなかった要件 0`）。
