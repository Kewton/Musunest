## 0. 一言でいうと

利用者の依頼文から、**アプリの宣言（`app.spec.yaml`）を 1 枚作るエージェント**をプロダクトの中に持つ。
作った宣言は **CommandAgent と同じ納品物の形**で出し、同じ門を通して publish する（工場は 2 つ・契約は 1 つ）。

## 2. 根拠（#168 の試験。PR #258）

| | 一発生成（第 5 段・10 × 5） |
|---|---|
| 最後の静的チェック | 50/50 |
| 書ける題材（A・C・E）の宣言の合格 | 機械 23/30、人の確認後 24/30 |
| 一部書けない題材（B・D）の挙げ漏れ | 機械 5/20、人の確認後 0/20 |
| 無い語彙の発明 | 0 |
| 費用 / 時間 | 50 本で 0.14 USD / 1 本 13〜35 秒 |

**残った不合格は、ほとんどが「静的チェックは通るが要件を落とした」ものだった**（回数を落とした・登録の操作が無い・印を付けない）。
一発生成の仕組みには、要件と宣言を突き合わせる段が無い。**エージェントにする理由はこれである。**

## 4. 進め方（段階）

| 段階 | 中身 | Cloudflare を使うか |

段階 1 で品質の基準（`03` §4）を満たすまで、段階 3 に進まない。
