## 0. なぜ役割の違う組を持つか

落ちの中身を見て直した組は、その組に適応する。だから、**直しの根拠にする組**（読んでよい）、**壊していないかを数える組**（落ちを調べない）、**一般化を 1 回だけ確かめる組**（封）を分ける。受入の P1〜P10 は開発と受入の比較に使われ、独立した回帰用はまだ無い。保留の 15 題材は別に封がある。

## 1. 3 つの組

## 3. 指標と分母

- **合格の数は、凍結した外部の採点（v5）の PASS を基本にする。** 工場の `full`・`partial`・`none` は別に記録する。`full` が増えても、除外した要件や未点検の申告が増えただけのことがある
- **Build 評価 v1.2 の手 3b 以降の wave の受入の主指標は、要件単位の正答率（欠け・過剰・確かめ方。表の採点 1・#612）と C3 の正誤表（見逃し・誤拒否。表の採点 2・#614）にする**（2026-10-18・所有者が決定。窓口の調査（2026-10-18）の推奨）。外の採点の PASS は漏斗の「納品」の段として副に置き、変えた段の通過率の対の差（`08` D6）は変えた段の指標として残す。**v1・v1.1α の比較元の読み方は上の行のまま変えない。**
- Plan を通す組は、**原文の充足と了承後の充足を別に数える**（所有者の決定⑥）
- **要件の分母は、原文系・了承後系それぞれ採点定義から決め、生成失敗・静的 NG は充足 0 としてその分母に残す**（`03-evaluation.md` §4 の「失敗した本も分母に入れる」を充足率にも当てる）。**予定した本・実行した本・未実行の本を照合し、未実行が残る計測は「未完了」と表示して正式な比較基準にしない。** これらを含む正例・負例を API 不要で確かめ、前後は同じ集計の版で採点する。補正の前の計測の充足率は、この文書の比較に使わない
- 新しい組にも、静的チェック・挙げ漏れ・充足率・誤った申告・無い語彙・時間と費用の分母を**セットの定義に固定**する。書ける題材の率は、その対象の本数を分母にする（今の受入 50 本の分母は 30）
- F1（P3 の独立の点検）・P5 後の差分の点検・二系統の採点が整うまで、**自動の計測を成績の確定に使わない**（確定は所有者の決定⑤）
- Plan 評価の原文の取りこぼし・水増しは、正解の文（必ず要件になるべき文）との照合を正規表現の鍵で**採点のコード**に置く。工場の記録の覆い（`confirm_coverage`）は自己採点になるので診断の参考にとどめる。往復ごとの待ち時間は `plan-record.json` の段の `duration_ms` から出す

## 4. 前後比較の読み方

| 決まり | 理由 |
|---|---|
| **意図した変更以外の比較条件を固定する。** 題材・採点定義・モデル・effort・締切・予算の適用単位をそろえる。**実行と採点が参照する内容の指紋と、有効な adapter・モデルの構成を記録する**：工場と spec-engine の dist、生成に渡す文書（契約・語彙の意味・語彙の台帳。`cli.ts:486-495`）、採点定義と集計（`subjects/*.json`・`engine.mjs`・`score-agent.mjs`）、判定の口の構成（Jev を主に LLM を落とし先にするか、LLM だけか。`cli.ts:247-258`。環境で切り替わる）、並列の数（`concurrency`。429・529 の再送の待ちが締切を食うので生成条件）・台本と凍結の組の指紋。鍵そのものは記録しない。**意図した変更の範囲を宣言し、それ以外の差があれば同じ条件の比較や基準の再利用として扱わない** | commit や dist を前後で同一にする条件ではない。同じコード・引数でも判定の構成が違えば別の条件で、変更の効果を分離できない |
| **対象のモードが 0 件なら「今回未観測」と書き、その段まで到達した本数を添える** | 0/20 でも区間の上限は 16% ある。停止が前の段へ移って未観測になることもある |
| **合格数の増減は探索の信号として扱い、固定の本数の差で雑音・改善を断定しない** | 同じ性能でも、10 パターン × 3 回の前後でどれかが 2 本減ることは珍しくない（独立・確率 1/2 なら約 69%）。固定の差を使うなら暫定の警報と明記し、比較の履歴がたまったら題材と条件ごとに見直す |
| **門の違反は即時に止める。それ以外の劣化の疑いは同じ条件で確認計測し、結果と不確かさを並べて次の wave の可否を決める** | 1 回の差で戻すと、戻す判断も雑音に乗る |
| **確認計測を挟むのは、(i) 戻す・merge を見送る判断をするとき、(ii) 差が P 単位の区間で 0 をまたぐのに merge の可否を決めるとき。すべての前後比較を 2 回にはしない。戻したあとの測り直しは確認計測を兼ねてよい**（2026-10-18・所有者が決定） | 判断に効くときにだけ費用を払う。反復 K を 3 から上げるのは、雑音の分解で予測の雑音（同じ P の反復のぶれ）がデータの雑音（P の違い）に勝つときだけ（`08` §8.7） |
| **判定は P ごとの対の差の数と、率の差の区間で読む。比較元と候補は同じ時間帯に交互に流す。同じ版の反復で測った幅は暫定の警報** | 同じ版で 1 回 10 本の確定が 1/10〜7/10 と動く。原因が時間帯なら対で相殺できる。独立 2 群では 30 本で +35 点以上しか言えない（見込み） |
| **Wilson の区間は固定した組での実行のばらつきの参考として示す。同じ版の反復は任意の予備計測で、1 回の比較で普遍の閾値を決めない** | 50 本は既存の受入の本数であって、90% を保証する最小の本数ではない。得られるのは 10 個の小さな前後差で、別の題材・effort・版に同じ線を当てる根拠は無い。未知の題材への一般化は保留の組で確かめる |
