## 0. 一言でいうと

**直す単位を「落ち 1 本」から「共通の原因」へ、直す場所を「プロンプト」から「契約とコード」へ、効いたかの判断を「1 本の印象」から「同じ条件の前後比較」へ移す。どの直しでも、意味の独立の点検と門は保つ。**

## 1. 約束（3 つ。理由つき）

1. **測ってから直し、同じ条件で前後を比べる。** 1 本の落ちは原因を特定していないし、前後の比較が無ければ「直った・壊した」は言えない。少数の計測は停止の経路を読むためだけに使う（`01`）
2. **共通の原因と、観測の外にも効く根拠を示してから直す。** 1 件に効く直しは分岐を増やし、未知の入力で壊れる。原因の一般性は件数ではなく、契約の因果と別の構造の反例で示す（`02`）
3. **コード・契約・入力から直す候補を先に検討し、意味の独立の点検と門を保つ。** プロンプトの規則は最も手軽で最も散らかる。事実の持ち主を 1 つにしても、その事実の意味が正しいことは別に点検する（`03`・`04`）

## 3. 恒久の決まりと、今回だけの実施計画

`01`〜`05` と台帳の列の定義は恒久の決まりである。`06` の §0 は恒久の進め方（段階）、§1 以降は**今回だけの実施計画**で、所有者の採否のあとに更新し、終わった項目は消す。固定の本数・文数・期間は、根拠を書けるものだけを置く。

## 4. 言葉

| 言葉 | 意味 |
|---|---|
| 落ち | 1 本の計測で出た 1 つの問題（停止の理由・部分案の理由・不一致・未解決・対応表の落ち） |
| 共通の原因（モード） | 複数の落ちを 1 つの変更で防げると、証拠で示した箇所。件数の条件ではない |
| 今回未観測 | その計測で 0 件だったこと。「直った」の確定ではない。到達した本数を添える |
| 事実の持ち主 | ある事実を**表現として**決める 1 つの段。意味の正しさは別に点検する（`03` §3） |
| 門 | 合否・持ち主・納品先をコードが決める検査。fail-closed。緩めない |
| 統合候補 | 1 wave の PR を比較元（base）に重ねた、計測とレビューの対象。管理が作る（`05` §3） |
| human-only | 窓口（人の側）だけが変え、人が読んで merge するもの（workspace の台帳・計測の道具・評価セット・運用文書） |
