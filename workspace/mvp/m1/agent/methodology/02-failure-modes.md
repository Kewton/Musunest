# 02：失敗の分類

> 状態：**採用 v3**（2026-10-12・所有者が採用）。台帳の実体は [`ledger/failure-modes.md`](./ledger/failure-modes.md)。

## 0. なぜためてから分類するか

落ちを 1 本ずつ直すと、その 1 本に合わせた分岐が増える。複数の落ちを並べて初めて、同じ変更で防げる箇所（共通の原因）と、入力に固有の事情が分かれる。分類は直す前に行い、**優先度は頻度と重大さ**で、**直し方の一般性は契約の因果と別の構造の反例**で決める。件数だけで直す・直さないを決めない。

## 1. 台帳の列

観測・成果物・原因を**別の列**にする。1 つの層に押し込むと、担当者によって分類が変わる。

| 列 | 中身 |
|---|---|
| ID | `M-nn`。消さない。合成の例の試験の名前に入れる |
| 症状 | 記録の文言の型（`stop_reason`・`partial_reasons`・不一致の型）。**値（役割 ID・要件 ID・題材の言葉）を書かない** |
| **観測した段** | ①〜⑧・P1〜P6 のどこで止まった・落ちたか |
| **誤った成果物** | 何が間違っていたか（確定した仕様・設計・固定した試験・対応・宣言・判定・記録） |
| **原因の種類**（複数可） | `記録と計測`／`入力の欠落`（契約にはあるが段に渡していない）／`契約の欠落`（段がその事実を知る欄が無い）／`返り値と経路`（落ちが直せる段に届かない・同じ要求を繰り返す）／`受け持ち`（上流から決まるものを LLM が書く・評価器が確かめられない）／`規則`（無い・曖昧・矛盾）／`能力`（情報も規則も足りているのに当たらない。effort の比較の証拠が要る） |
| **主因** | **その変更だけで失敗を防げると、証拠（ファイル:行と記録）で示した箇所**。番号や順番で決めない。証拠が足りなければ「未確定」、複数なら併記 |
| 観測 | 計測 ID × 本。**症状の件数・失敗した本数・パターン数を別々に**書く |
| 直しの候補 | `03` §1 の段と、採らない候補の理由 |
| 状態 | 未着手／Issue #n／直った（再現試験で原因の解消を確認）／今回未観測（計測 ID）／受け入れる（§3 の根拠）／**旧版の劣化**（回帰用の版。題材を開発用へ移しても消さず、解消か受け入れまで追う。`01` §1） |
| 不要になる規則 | `ledger/rules.md` の ID |

- 分類は 1 人が仮に置き、調査（Claude_sub）かレビュー（Codex）が独立に付け直す。**食い違いは台帳に残す**（同じ落ちを 2 人が別の種類にしたなら、定義のほうを直す材料になる）
- 症状が違っても主因が同じなら ID を参照で結ぶ。**重複して数えない**

## 2. いつ分類し、どう直すかを決めるか

| 決まり | 理由 |
|---|---|
| 開発用の計測 1 回（20 本）ごとに観測と分類を見直す。少数の診断でも原因の調査と仮説は記録できる。主因の確定にはコード・再現・反例の証拠を使う | 本数は調査を禁止する線ではない。前の段で止まって後の段を観測できなかった本を区別する |
| **修正の優先度は頻度と重大さで決める。** 原因の一般性は、契約の因果と、観測していない別の構造の反例で確かめる | 頻度は「よく出る」ことしか言わない。1 パターンで繰り返す契約違反は一般的でありうるし、2 つの effort で同じ入力を流せば件数は増える |
| **単発でも原因の調査は行える。** ただし**入力に固有の規則は足さない**。観測の外にも効く因果を示せたコード・契約の修正は候補にする | 調査を禁じると、契約の欠落を見逃す。規則で塞ぐと、その入力にしか効かない |
| **件数によらず直すもの**：門の違反（合格でないものを `full` にする）、誤った了承・除外（書ける要件を落とす）、上限の不遵守（予算・締切・回数の門が効かない） | 正しさの不具合は頻度の問題ではない。直し方はコード・契約（規則で直さない） |
| **正常な上限の停止は暴走に数えない。** 再発しない単発は「今回未観測」として保留する。直して別の落ちが出たら新しい行を立て、戻すかは `01` §4 の確認計測で決める | 上限で止まるのは設計どおり。消えた単発を直したことにしない。1 回の差で戻す判断も雑音に乗る |

## 3. 残る失敗を受け入れる基準

受入の線（`03-evaluation.md` §4）を上げない。線を超えたあとに残る失敗は、次の**すべて**を満たすときだけ「受け入れる」と台帳に書ける。

1. 門の違反・誤った了承や除外・上限の不遵守のどれでもない
2. 契約の因果で説明できる共通の原因が見つからない（調査済み）、または直すと複雑さが増す理由を書ける
3. 利用者には部分案として、できなかったことが**正しく**出る（挙げ漏れ 0・誤った申告 0）。**書ける要件の充足率を落としていない**（部分案の正しい申告は指標の 1 つであって、書ける要件を落としてよい免除ではない）

- 受け入れた失敗も台帳に残し、保留の組の結果でも同じ種類が出るかを見る。受け入れは、その本を `full` にすることや、部分案を publish の門へ通す許可ではない
